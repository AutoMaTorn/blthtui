# bluetui

*[English version](README.md)*

Лёгкий и быстрый TUI для управления Bluetooth в Linux, в стиле `nmtui`.

Написан на C поверх **BlueZ** (через `sd-bus` из libsystemd), интерфейс — на
**newt**, той же библиотеке виджетов, что использует `nmtui` из
NetworkManager. Ни Python, ни собственного демона, ни графического окружения:
работает везде, где есть терминал и запущенный `bluetoothd`.

## Возможности

- Включение и выключение Bluetooth-адаптера
- Поиск устройств поблизости
- Подключение и отключение (Enter на устройстве)
- Сопряжение, доверие и удаление устройств
- Интерактивное сопряжение: ввод PIN-кода и passkey, диалоги подтверждения
  (программа регистрируется как агент BlueZ `org.bluez.Agent1`)
- Подключение и сопряжение выполняются асинхронно — интерфейс не замирает и
  показывает ход операции
- Детали устройства по запросу: уровень заряда (через `org.bluez.Battery1`),
  тип устройства и UUID сервисов
- Фильтр списка по имени и режим «только сопряжённые»
- Выбор адаптера, если их несколько
- Живой список — обновляется прямо по сигналам BlueZ (устройство появилось или
  исчезло, подключилось, изменился RSSI), а не перечислением по таймеру;
  изменение RSSI не переставляет строки под курсором
- Метки сопряжённых (`+`) и подключённых (`*`); подключённые и сопряжённые
  устройства идут первыми, остальные — по силе сигнала
- Имена устройств на любом языке отображаются корректно (учёт UTF-8 и ширины)
- Ввод PIN и passkey скрыт (как пароль) и проверяется
- Чистый выход по Ctrl-C / SIGTERM: останавливается запущенный нами поиск и
  снимается регистрация агента сопряжения

## Сборка

Нужны пакеты Debian/Ubuntu:

```sh
sudo apt install build-essential libnewt-dev libsystemd-dev pkg-config
make
```

## Запуск

```sh
./bluetui
```

`bluetoothd` должен быть запущен, а ваш пользователь — состоять в группе
`bluetooth`. Права root не требуются.

## Клавиши

| Клавиша        | Действие                              |
|----------------|---------------------------------------|
| Вверх / Вниз   | Перемещение по списку устройств       |
| Enter          | Подключить / отключить выбранное      |
| `p`            | Сопрячь выбранное                     |
| `t`            | Переключить доверие к выбранному      |
| `d`            | Показать детали устройства            |
| `r`            | Удалить выбранное                     |
| `s`            | Начать / остановить поиск             |
| `/`            | Фильтр списка по имени                |
| `o`            | Показывать только сопряжённые         |
| Tab            | Переход между списком и кнопками      |
| F10 / Esc / q  | Выход                                 |

## Установка на другие машины

### Сборка .deb (рекомендуется)

```sh
sudo apt install build-essential debhelper libnewt-dev libsystemd-dev pkg-config
dpkg-buildpackage -b -us -uc          # создаст ../bluetui_<версия>_amd64.deb
```

Скопируйте получившийся `.deb` на любую машину с Debian или Ubuntu и
установите — `apt` сам подтянет зависимости (`libnewt0.52`, `libsystemd0`,
`bluez`):

```sh
sudo apt install ./bluetui_0.2.1_amd64.deb
```

Удаление: `sudo apt remove bluetui`.

Вместе с основным пакетом собирается `bluetui-dbgsym_<версия>_amd64.deb`. В нём
лежат только отладочные символы: `dh_strip` вырезает их из бинарника и
связывает с ним по Build-ID. Для работы bluetui он не нужен — ставьте его рядом
с основным пакетом, когда нужен читаемый бэктрейс в `gdb` или при разборе core
dump.

## Отладка

**Режим лога.** Укажите в `BLUETUI_LOG` путь к файлу, чтобы записывать каждый
вызов D-Bus, его результат и текст ошибки (без переменной ничего не пишется):

```sh
BLUETUI_LOG=/tmp/bluetui.log ./bluetui   # затем в другом терминале:
tail -f /tmp/bluetui.log
```

**Сборка с санитайзерами.** `make debug` создаёт `./bluetui-debug` с
AddressSanitizer и UndefinedBehaviorSanitizer — они ловят утечки и некорректную
работу с памятью в ручном разборе сообщений sd-bus.

**Headless-харнесс.** `make test` создаёт `./bttest` — он дёргает слой BlueZ
(`bt.c`) без TUI, что удобно под `gdb` или ASan: newt не борется за терминал.
Это смоук-харнесс для отладки, а не набор тестов: он печатает адаптер, его
состояние и список устройств, ничего не проверяя.

```sh
make test && ./bttest
```

**Юнит-тесты.** `make check` собирает и запускает `tests/test_strutil.c` —
обычные проверки чистых функций (UTF-8-дополнение, сортировка устройств,
фильтр по имени, разбор passkey). Ни D-Bus, ни newt, ни железа не нужно.

```sh
make check
```

**Живая трассировка D-Bus** (сборка не нужна):

```sh
busctl monitor org.bluez            # весь трафик BlueZ
busctl introspect org.bluez /org/bluez/hci0
```

> `make` и `make debug` линкуются с `-lnewt`, поэтому им нужен `libnewt-dev`.
> `make test` newt не линкует и собирается без него.

## Структура

```
src/
  device.h     модель устройства
  bt.c/.h      доступ к BlueZ через sd-bus
  ui.c/.h      интерфейс на newt + главный цикл
  strutil.c/.h чистые функции: UTF-8-дополнение, сортировка, фильтр, passkey
  log.c/.h     опциональный файловый лог (BLUETUI_LOG)
  main.c       точка входа
tools/
  bttest.c     headless-харнесс для отладки (make test)
tests/
  test_strutil.c  юнит-тесты чистых функций (make check)
debian/        сборка пакета Debian (native 3.0, debhelper 13)
```

`bt.c` не касается интерфейса: агент сопряжения общается с UI только через
структуру колбэков `bt_agent_cb`. Именно поэтому headless-харнесс собирается
без newt.

## Известные ограничения

- Файловый дескриптор шины слушается только на чтение; в редком случае, когда
  sd-bus нужно писать или есть собственный таймаут, он обслуживается по
  запасному таймеру в 4 секунды.
- Диалог сопряжения, оставленный без ответа дольше 180 секунд, завершается
  таймаутом.
- Список устройств ограничен 256 записями; при переполнении показывается строка
  «list full».
- Выбор адаптера предлагается только при запуске — переключения на лету нет
  (пропавший адаптер подхватывается обратно автоматически).
